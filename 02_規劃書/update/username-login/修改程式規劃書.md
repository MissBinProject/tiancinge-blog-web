## 3. 推薦架構

使用單一管理員「帳號別名」。登入 use case 將 tiancinge 對應至原 Firebase Email，再由 Firebase 驗證密碼。登入成功沿用同一 UID、Firestore allowlist 與 Storage claim，無須新增帳號或資料遷移。

流程：帳號＋密碼 → 本地格式驗證／帳號對應 → Firebase 密碼驗證 → 管理員權限驗證 → 後台。

Firebase Email/Password 原生以 Email 驗證，因此這是使用者介面的帳號登入，不是移除 Firebase 內部 Email 身分。帳號對應會隨前端程式發布，對應 Email 可被技術使用者檢視；不得將其視為機密或權限控制，也不能宣稱原 Email 從 Firebase API 端失效。若未來要求隱藏 Email 或完全禁止 Email 驗證，需另行規劃伺服器自訂驗證。

不新增 Cloud Run endpoint、Cloud Function、Firestore 帳號對照集合或密碼資料表。本次不新增登入伺服器運算費；既有 Firebase／Hosting 計費仍依平台用量。

## 4. 模組與固定契約

```text
apps/admin/src/features/auth/
  domain/username.ts           # 正規化、驗證、對應契約
  application/accountLogin.ts  # 帳號登入／忘記密碼用例
  infrastructure/accountConfig.ts # 單一管理員非秘密對應
  presentation/LoginPage.tsx   # 登入與忘記密碼入口
apps/admin/src/auth.ts         # 保留 Firebase adapter 與 session API
apps/admin/src/main.tsx        # 組合登入頁，保留既有 session 世代防護
```

domain 不引用 React、Firebase。畫面只呼叫 application；application 以注入的 adapter 呼叫現有 auth.ts。保留 React Router 與現有 session 狀態，不增加全域 store、不搬動其他管理頁。此功能不擴張 packages/contracts，以免影響官網。

- normalizeUsername(raw)：去頭尾空白、轉小寫；4–32 字元，僅 a-z、0-9、底線與連字號。
- 密碼保持使用者原字串，不 trim、不轉大小寫；空字串才是空密碼，不自行提高既有登入密碼限制。
- signInWithUsername(username,password)：回傳現有 AdminSignInResult；錯誤帳號／錯密碼統一「帳號或密碼不正確」。網路／設定／權限錯誤維持可辨識回饋。
- requestResetByUsername(username)：成功或未知帳號顯示「若帳號有效，重設信件將寄至綁定信箱」。不顯示完整收件地址，不開放輸入任意收件信箱。
- Firebase 操作保留於 auth.ts；錯誤碼辨識 invalid-credential、too-many-requests、network-request-failed，必要時新增 rate-limited reason，所有呼叫端同步。
- 登入後仍驗證 admins/{uid}，不能用帳號字串判定管理員；不新增正式環境 fixture 登入捷徑。

## 5. UI 與密碼恢復

沿用現有 Logo、登入卡片與配色。帳號 input：type=text、autocomplete=username、autocapitalize=none、spellcheck=false；placeholder「請輸入帳號」。密碼保留 autocomplete=current-password。

按 Enter 登入；送出中停用重複送出；失敗保留帳號、可重新輸入密碼。窄螢幕 390px 與桌機 1440px 無溢出，label、錯誤 aria-live、鍵盤焦點完整。

忘記密碼先輸入帳號，再送 Firebase 重設郵件；測試只能寄至測試帳戶或由本人操作。採 Firebase 預設 hosted action handler 完成密碼重設，再回後台。現有 PASSWORD_RECOVERY 事件不由 onAuthStateChanged 產生，不能誤把該分支當成可用重設流程；本次移除未接線的自訂 recovery 畫面／事件前須核對引用。不強迫更換正式密碼。

## 6. 發布與回退

先測試環境驗證同一 UID 與權限，再建置後台，僅發布 firebase.json 指向 tiancinge-admin 的 Hosting target。保存前一版 Hosting release ID 與 Git commit；不重新部署官網 Cloud Run 或放寬 Rules。

發布後驗證一般帳號登入、重新整理 session、登出、服務清單讀取及合法素材權限。正式測試密碼僅由安全環境輸入，不寫 repo、log 或截圖。缺少測試憑證時標記未驗證，禁止記為通過。

若登入故障，從 Firebase Hosting 回退上一版後台，恢復 Email 表單；因 UID、密碼與 Rules 未遷移，無須還原資料庫。未完成驗收前不移除前版部署。
