# SEO 基線證據

檢查日期：2026-09-18（Asia/Taipei）。這份紀錄是開發前基線，不能解讀為 Google 收錄或排名保證。

## 公開端點

| 端點 | 觀察結果 |
| --- | --- |
| `https://tiancinge-web.web.app/` | HTTP 200；伺服器回傳頁面標題、描述、canonical 與正文摘要 |
| `https://tiancinge-web.web.app/blog` | HTTP 200；列表內容由伺服器輸出 |
| `https://tiancinge-web.web.app/blog/edxei4o1pk` | HTTP 200；詳情內容、metadata 與結構化資料由伺服器輸出 |
| `https://tiancinge-web.web.app/sitemap.xml` | HTTP 200、`application/xml`；XML 可解析，當時含 18 個不重複 URL |
| `https://tiancinge-web.web.app/robots.txt` | HTTP 200；含 sitemap 宣告，並禁止 `/api/` 與 `/search` |

## Sitemap／Search Console

- 18 個 sitemap URL 在基線檢查時均回傳 HTTP 200。
- Search Console 曾顯示 sitemap「無法擷取」；重新提交後 Google URL Inspection 的即時測試顯示 sitemap 可抓取、robots 允許、頁面擷取成功。
- 因此當時較可能是 Search Console 報表延遲或處理狀態，而非 XML 本身格式錯誤；L05 與 L24 仍要保留可重現檢查及提交後證據。
- sitemap 本身沒有被 Google 索引，不代表 sitemap 不能被讀取；驗收應查看 Sitemap 報表的抓取狀態與 URL 數量。

## 已知基線缺口

- `/search` 同時受頁面 `noindex` 與 robots `Disallow` 影響，需統一為允許爬取、由 `noindex,follow` 控制索引。
- 文章尚未完整記錄來源、實質內容更新日期與固定編輯團隊資訊。
- 分類公開頁、文章目錄、相關文章與一般 HTML 入口仍需補齊。
- `loadArticle` 與文章列表目前以集合載入後在記憶體篩選，資料量增加時需改精確查詢與資料庫分頁。
- 圖片已有 alt／WebP 基礎，但需補 responsive `sizes`、比例與載入策略驗收。

## 重跑方式

L01 應把上述端點檢查變成可重複執行的腳本；L24 需在 staging 與正式環境各跑一次，將實際命令、提交時間、Search Console 狀態與未完成外部項目填回交接紀錄。
