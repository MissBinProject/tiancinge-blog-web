# 移除 Firebase Authentication：單一伺服器帳密登入

日期：2026-09-15。狀態：核心實作、Cloud Run、Firebase Hosting 與回退演練已完成；桌機像素差異與 provider 停用決策仍列為維運後續。此規劃取代 username-login 中 Firebase Email 別名登入方案；舊文件保留為歷史紀錄，其完成勾選不作為本次驗收證據。

## 1. 目標與範圍

後台只用一組一般帳號與密碼登入，不使用 Firebase Authentication、Email 別名、custom token 或 Auth 重設信件。預設帳號 tiancinge；密碼於實作時由操作者安全輸入並產生雜湊，不在本文件沿用或抄寫對話中的明文密碼。

保留官網 Next.js 動態 SSR、後台 React/Vite、Firestore、Cloud Storage 與 Firebase Hosting。單一管理員，沒有公開註冊、多帳號或角色管理。所有既有服務、消息、部落格、分類、素材、留言、網站設定與政策功能必須繼續運作。

## 2. 現況與影響（依本機程式檢查）

- apps/admin/src/auth.ts 使用 Firebase Email/Password、session observer、admins/{uid}；不是獨立帳密驗證。
- apps/admin/src/features/auth/infrastructure/accountConfig.ts 將一般帳號對應 Email。
- apps/admin/src/repositories.ts 直接使用 Firestore Web SDK 及 Storage Web SDK，涵蓋七類內容；缺設定時部分操作會回報成功，正式新模式必須改為明確失敗。
- firestore.rules 以 Firebase request.auth 與 admins allowlist 授權；storage.rules 以 admin custom claim 授權。移除 Auth 後原有請求全部失去授權，不能靠放寬 Rules 修補。
- apps/admin/src/main.tsx 共 381 行，包含登入/session 協調；只抽出相關登入責任，不重寫全部後台。
- apps/web/src/lib/firebase-admin.ts 已提供伺服器 Firestore/Storage ADC 連線，可沿用。Firebase Admin SDK 名稱不代表使用 Firebase Authentication；僅保留資料與儲存 SDK。
- firebase.json：web 已 rewrite 至 asia-east1 的 tiancinge-web；admin 目前只有靜態輸出，須加 /api/admin/** rewrite，再加 SPA fallback。

## 3. 建議架構

```text
管理員瀏覽器 → tiancinge-admin.web.app（靜態 React）
             → 同源 /api/admin/**（Hosting rewrite）
             → 既有 Cloud Run / Next.js Route Handlers
                 ├─ 伺服器帳密驗證與 session 檢查
                 ├─ Firestore Admin SDK（資料、session、限流）
                 └─ Cloud Storage SDK（圖片）
```

不新增第二台長駐主機。後台 API 會增加既有 Cloud Run 請求及 Firestore 讀寫；沿用最小執行個體 0。此方案不保證零費用，也不將預算通知視為即時硬停機。Cloud Run 停用時官網 SSR、登入與管理 API 都受影響，靜態登入頁仍可載入。

## 4. 帳密、Cookie 與重設

| 設定 | 存放位置 | 規則 |
|---|---|---|
| ADMIN_USERNAME | Cloud Run runtime env | 正規化為小寫、去頭尾空白，4–32 位英數、底線或連字號 |
| ADMIN_PASSWORD_HASH | Secret Manager，指定版本注入 runtime env | scrypt 加隨機 salt；格式包含版本、參數、salt、hash；參數固定並限制解析範圍；constant-time 比對 |
| ADMIN_CREDENTIAL_VERSION | runtime env | 更換密碼或帳號時遞增，撤銷舊 session |
| ADMIN_ALLOWED_ORIGIN | runtime env | 正式固定 https://tiancinge-admin.web.app；測試站獨立設定 |

本機使用被 Git 忽略的 apps/web/.env.local；.env.example 只有空白佔位。不得使用 VITE_*、NEXT_PUBLIC_*、Docker build ARG 或前端常數保存密碼/雜湊。密碼建立工具採隱藏互動輸入，不放 CLI 參數、shell history、log 或 Git。正式缺設定回 503，不使用預設密碼或 fixture 登入。

登入成功產生至少 32 bytes 的隨機 session token，Cookie 為 __session、Secure、HttpOnly、SameSite=Strict、Path=/、不設 Domain，絕對有效期 8 小時、不自動延長。選 __session 是為相容 Hosting 動態轉送；實作必須驗證 Cookie 往返。Firestore admin_sessions 只存 token 的 SHA-256、建立/到期時間、credentialVersion 與 CSRF token 雜湊；請求每次檢查存在、到期與版本。TTL 僅清理，不作授權依據。登出刪 session 並清 Cookie；瀏覽器重整由 GET session 恢復。不得把 session token 存 localStorage。

CSRF：session 回應提供隨機 CSRF token（前端僅存記憶體），所有內容異動/登出要求 X-CSRF-Token 與精確 Origin；登入同樣驗 Origin 且僅接受 JSON。禁止 wildcard CORS。所有管理 API 含登入錯誤回應均 Cache-Control: private, no-store；不公開快取登入或草稿。

移除忘記密碼寄信與 recovery UI，改提示「請聯絡網站維護者重設」。維護者重新產生 hash、建立 Secret 新版本並更新 credentialVersion、部署單一新 revision、確認舊 session 失效。第一版不新增線上修改密碼頁。回退不能復活已撤銷憑證版本。

## 5. API 與資料契約

統一回應 {ok:true,data} 或 {ok:false,error:{code,message}}。狀態碼：400 驗證失敗、401 未登入、403 CSRF/來源拒絕、404 不存在、409 引用衝突、413 過大、429 限流、503 缺設定/服務不可用。不得向訪客回傳 SDK 原始錯誤或堆疊。

| 路由 /api/admin 下 | 方法 | 輸入/結果 |
|---|---|---|
| /auth/login | POST | username,password → 設 Cookie，回 username,expiresAt,csrfToken |
| /auth/session | GET | 回 username,expiresAt,csrfToken；無效回401 |
| /auth/logout | POST | 撤銷目前 session；無有效 session 仍可清 Cookie |
| /services | GET,POST | 列表/新增，維持既有 Service 欄位 |
| /services/:id | PATCH,DELETE | 編輯、排序、顯示、刪除 |
| /articles | GET,POST | type=news/blog,status,q,cursor,limit；新增草稿 |
| /articles/:id | GET,PATCH,DELETE | 草稿詳情、編輯、發布、下架 |
| /categories | GET,POST | type 分類 |
| /categories/:id | PATCH,DELETE | 使用中不可刪除 |
| /settings | GET,PATCH | singleton 白名單；含首頁與政策 |
| /messages | GET | status,cursor,limit |
| /messages/:id | PATCH,DELETE | 僅 status,note 可修改 |
| /media | GET,POST | 列表；multipart 單圖上傳 |
| /media/:id | PATCH,DELETE | alt 編輯、引用檢查後刪除 |

列表 limit 預設20、上限100；回 items,nextCursor。q 第一版在服務端有界分批掃描标题/摘要，固定每次最大掃描200筆，cursor 記錄掃描位置，無精確 total；若當頁無命中但仍有 cursor，UI 可继续翻頁，不宣稱全站無結果。按既有索引與穩定 id 次排序，明定 Firestore 索引；不把所有文章下載到瀏覽器搜尋。既有10位亂碼 slug 保留，新建由 server 產生並檢查碰撞；編輯不得任意換碼。

沿用既有七類集合與欄位；新增 admin_sessions、admin_login_guards，均禁止瀏覽器直接讀寫。登入限流以 Firestore transaction 實現跨執行個體一致性，採伺服器確認的來源 IP 雜湊加短時窗（每15分鐘10次），IP 不信任任意 X-Forwarded-For；若 Hosting 路徑無可靠 IP，先完成來源驗證設計，不使用可偽造欄位作唯一限制。額外帳號全域速率保護不採永久鎖定；逾限回429+Retry-After。未知帳號也执行固定假 hash 驗證，避免時序洩漏。

圖片 JPEG/PNG/WebP、10MB，server 同時檢查長度、MIME、檔頭與解碼結果；限制像素與記憶體用量。物件路徑 server 產生，只允許 site-media/；保留現有 URL 可讀性。優先由 API 代理上傳；失敗回收孤兒檔。素材選取/刪除採引用紀錄與刪除狀態鎖，所有內容儲存同步檢查素材有效性，防止檢查後被重新引用。分類引用也須在交易內檢查，不能只靠 UI。

## 6. 模組邊界

```text
apps/web/src/features/admin-auth/{domain,application,infrastructure}/
apps/web/src/features/admin-content/{services,articles,categories,settings,messages,media}/
apps/web/src/app/api/admin/…/route.ts       # 薄路由：驗證→use case→response
apps/admin/src/features/auth/              # HTTP session/use case/登入畫面
apps/admin/src/features/*/infrastructure/  # 各功能 HTTP adapter
packages/contracts/src/admin/             # DTO/驗證，不含秘密或 SDK
scripts/                                  # 安全建密碼/部署驗收工具
```

保留 React Router、既有頁面與共用資料型別，不新增全域 store。domain 不引用 Firebase/React；畫面只呼叫 use case/repository；server 用 ADC 與最小 IAM 權限，每條 API 都驗 session，因 Admin SDK 繞過 Rules。公開官網查詢仍只讀已發布內容，公開 contact API 保留原驗證及限流。

## 7. 遷移、部署與回退

1. 建立測試專案/隔離資料与基線；盤點所有 SDK 呼叫，不以旧文件勾選代替測試。
2. 建立契約、server 登入/授權，再逐功能 server API 與 HTTP adapter，通過一張卡才接下一張。
3. 在測試環境配置 Secrets、Hosting rewrite、Cookie，所有管理功能過關後才切正式。
4. 記錄 Hosting release、Cloud Run revision、Rules、秘密版本；先部署向後相容 API，再切後台與 rewrite，驗證後收緊 Rules。
5. 最終 Firestore 瀏覽器直接存取全部拒絕；Storage 保留既有公開圖片讀取，禁止瀏覽器直接寫入。後台已移除 Firebase Auth/Firestore/Storage SDK、Email mapping、舊 recovery 與正式 fixture fallback。不刪資料與既有 Auth 帳號作為切換必要步驟；確認專案沒有其他使用者後才可停用 Email/Password provider。
6. 在隔離站演練回退 API/frontend/Rules 配對版本；正式故障回已驗證版本，保留新 credentialVersion，不能只回退前端。最後才將舊 Auth 任務標記「被本方案取代」。
